### 1. ANSWER
No, the feature will not function correctly in production. It contains **two Blocker bugs**: (1) auto-promoted rows are immediately deleted by standard calendar/activity inference because stale row cleanup treats them as stale inferred rows; and (2) commit counting only reads from `github_commits`, which exclusively tracks Pull Request commits and completely ignores direct branch pushes (the most common developer workflow).

---

### 2. GRADED FINDINGS

#### 1. [Blocker] `_delete_stale_inferred_rows` Silently Deletes Auto-Promoted Projects
* **Citation**: [project_inference.py:L666-681](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/project_inference.py#L666-L681) (relying on [_is_inference_owned](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/project_inference.py#L73-L80) at line 674)
* **Description**: `sync_inferred_project_registry()` invokes [_delete_stale_inferred_rows](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/project_inference.py#L666-L681) with standard inferred project names. Since `_is_inference_owned` was generalized in Phase 1 to return `True` for `COMMIT_THRESHOLD_GENERATED_BY` ("commit_threshold_v1"), auto-promoted rows are identified as machine-owned. Because auto-promoted projects are not generated by the standard calendar/activity inference pass, they are absent from the inferred names list and get **silently deleted** on the next hourly/daily sync. 
* **Verification**: Proven via simulation; a newly promoted project registry row is cleaned up immediately upon standard inference sync.

#### 2. [Blocker] Commit Counting Only Covers Pull Request Commits
* **Citation**: [github_knowledge.py:L766-783](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/github_knowledge.py#L766-L783) (upsert source) and [project_inference.py:L779-800](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/project_inference.py#L779-L800) (query target)
* **Description**: [_count_operator_commits](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/project_inference.py#L779-L800) counts commits stored in the `github_commits` table. However, [github_knowledge.py](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/github_knowledge.py) only inserts commits into `github_commits` when synchronizing Pull Request pages via `pulls/{item_number}/commits`. Direct pushes to branches (e.g. `main` or `master`) are never fetched or stored in `github_commits`. Any repository where the operator pushes directly without opening a PR will show `0` commits and never promote.

#### 3. [Should] Name Casing Mismatch Causes Duplication and Collisions
* **Citation**: [project_inference.py:L810](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/project_inference.py#L810) (vs standard slug formatting in [project_inference.py:L173-181](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/project_inference.py#L173-L181))
* **Description**: [_repo_to_promoted_row](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/project_inference.py#L803-L830) extracts raw slugs for project names (`name = repo_full_name.split("/", 1)[-1]`), generating lowercase names like `widget`. Standard inference uses `_choose_display_name` to capitalize/format slugs (e.g. `Widget`). This casing mismatch results in duplicate project entries (e.g. `widget` and `Widget`) pointing to the same repo, which triggers secondary deletion bugs.

#### 4. [Should] Fail-Soft Wiring Masks Exceptions Silently
* **Citation**: [index_ops.py:L838-853](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/index_ops.py#L838-L853)
* **Description**: The try/except block wrapping [sync_commit_threshold_promotions](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/project_inference.py#L848-L910) in [_refresh_github](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/index_ops.py#L729-L882) swallows exceptions and folds them into the return dict without writing them to logs via `logger.warning`/`logger.exception` or propagating them to the orchestrator's primary `errors` list. Callers checking for operational errors (like daily sync cron jobs) will miss failures.

#### 5. [Nit] Case-Sensitive Bot Identity Match
* **Citation**: [pulse.py:L56-59](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/pulse.py#L56-59)
* **Description**: [_author_filter_sql](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/pulse.py#L56-59) evaluates operator identities case-insensitively, but delegates bot matches to the SQL `IN` operator against `CLOUD_AGENT_AUTHORS` placeholders. In SQLite, the `IN` operator is case-sensitive. Commits registered with different casing (e.g., `Claude[bot]` instead of `claude[bot]`) will fail to count toward the promotion threshold.

#### 6. [Nit] Project Name Collisions on Identical Slugs
* **Citation**: [project_inference.py:L810](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/project_inference.py#L810) and [registry.py:L177](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/registry.py#L177)
* **Description**: If the user works in two different repositories with matching slugs (e.g., `Acme/widget` and `Beta/widget`), both evaluate to the project name `widget`. In [sync_db](file:///Users/noelsaw/Documents/GitHub%20Repos/rebalance-OS/src/rebalance/ingest/registry.py#L165-L200), the `ON CONFLICT(name) DO UPDATE` clause will overwrite the first project with the second one, resulting in silent data loss/overwriting.

---

### 3. RECOMMENDATION
Isolate stale-row cleanup in `_delete_stale_inferred_rows` to `activity_inference_v1` markers only, and query Git pushes or direct branch commits instead of relying purely on the PR-centric `github_commits` table.
