## Compatibility Rules

1. A legacy entry point may remain a thin re-export facade only while at least one launchd plist, MCP tool, or shell-rc export still references its old import path or symbol name; remove the facade only in the same commit that updates that last external caller.
2. When a path-string contract changes (resolve_oauth_token_path's 'google-{service}-oauth', the canonical DB dir, REBALANCE_DB, or auth_log's dir), keep the old location readable as a fallback until a migration ships, then drop it only after `python -m rebalance.paths --migrate` (non-dry-run) has run and doctor is green.
3. Scheduler scripts may delegate to an extracted shared library, but the three job-name literals, the three scope lists, and the dict-with-'errors' return contract from refresh_index must stay byte-identical — never rename 'daily-sync' to 'daily_sync' or normalize a scope as part of the facade.
4. A renamed dashboard.py public symbol (any fetch_*, DB_PATH, TZ, _ago/_parse_iso/_truncate) must keep a shim alias in dashboard.py until both pulse_web.py's dashboard-import block and pulse_server.py's import block are updated and a one-shot `pulse_web.py --out` render succeeds; only then delete the alias.
5. QueryResult field names and the citation/temporal_context dict keys stay frozen until retrieval.py, cli/query.py, and querier._build_prompt are all routed through a single to_dict()/render helper; a field may be renamed only behind that helper, never by editing one consumer alone.
6. An OAuth setup script may keep its old filename/flags as a facade only until both the launchd consent flow and any docs invoking it are repointed; the byte-identical _CID/_CS constants must be deduped into one shared module before either script is deleted, so client rotation never edits two files again.

## Phase 1 Slice — Where to Start

Touch four files in this order. (1) src/rebalance/paths.py FIRST: it is the deepest dependency — config.py reaches into it (resolve_secret_path), auth_log resolves its log dir via resolve_project_root, and every collector/scheduler resolves the DB through resolve_database_path, so its _PROJECT_MARKERS, resolver order, and the 'google-{service}-oauth'/canonical-DB path strings must be settled before anything that imports them moves. (2) src/rebalance/ingest/config.py SECOND: it is the contract owner of rbos.config + keyring (KEYRING_SERVICE) and depends on paths.py one-way; dedupe its _PROJECT_MARKERS/_project_root_from against paths.py and consolidate the keyring-primary+rbos.config-fallback CRUD here while the resolvers underneath are frozen. (3) src/rebalance/ingest/auth_log.py THIRD: its FAILURE_EVENTS + source/job vocabulary is the data contract doctor/dashboard/scheduler all read, and its _log_dir() depends on paths.resolve_project_root, so lock it only after paths.py is stable but before the OAuth scripts that emit flow_started/succeeded/failed into it. (4) scripts/setup_calendar_oauth.py + scripts/setup_gmail_oauth.py LAST in this slice: extract the byte-identical _CID/_CS and the shared _build_client_config/authorize/--test bodies into one module, leaving the scope constant and service name as the only per-script differences — safe to do only once resolve_oauth_token_path (paths.py) and the auth_log flow-event functions above are settled, since both scripts depend on both.

## Cross-Subsystem Dependencies

- paths.py (resolve_database_path / DBOption / DatabaseNotFoundError, canonical DB path) -> Scheduler: all three sync scripts and the MCP refresh_index resolve the DB through it, so the resolver order and canonical path must be frozen before the scheduler scripts are refactored.
- paths.py (resolve_oauth_token_path 'google-{service}-oauth' + resolve_secret_path) -> Config/Auth (OAuth scripts + sleuth env): the setup scripts and the calendar/gmail collectors are writers+readers of these literal strings, so renaming them after the scripts move splits writers from readers.
- auth_log.py (FAILURE_EVENTS + source/job vocabulary + _log_dir via resolve_project_root) -> Pulse/Dashboard and Scheduler: doctor/dashboard read latest_failure_by_source and the scheduler writes job-name keys, so the event/source/job contract must be stable before those subsystems are touched.
- config.py (ingest.config getters: get_github_ignored_repos, get_pulse_config, get_figma_file_keys, focus5 hide/unhide, GMAIL_INGEST_METHODS) -> Pulse/Dashboard and Onboarding: dashboard/pulse_web and the gmail/registry paths import these accessors, so config's getter surface must be settled before the web and onboarding phases.
