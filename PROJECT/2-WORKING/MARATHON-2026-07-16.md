- **Contract:**

- **Acceptance:** re-run `daily_sync.sh` across a real or simulated `06:45` overlap with `github_sync.sh`; the resulting JSON `errors` list no longer contains a `github` / `"database is locked"` entry, and the `dashboard` scope stops being skipped with `"reason": "upstream refresh errors"`. `pytest tests/` green, `rebalance doctor` clean, `pdda.sh run` clean.
- **Out of scope:** the separate `github-sync` `Abort trap: 6` (SIGABRT) crash noted in the capture doc — different failure mode, not root-caused yet, tracked for a future issue if it recurs.

## Lane B — GH-121 Focus5Float `.md` telemetry viewer: size ceiling on the read

- **Paths:** `macOS/Apps/Focus5Float/Sources/Focus5Float/Focus5Model.swift` (`refreshTelemetry()`'s `.md` branch), `macOS/Apps/Focus5Float/Tests/Focus5FloatTests/TelemetryFileLoadingTests.swift`, `PROJECT/2-WORKING/GH-121-FOCUS5-TELEMETRY-MD-VIEWER.md`
- **Contract:**
  - The already-approved GH-121 Phase 1 plan (agy relay QA, 2026-07-06) called for a size ceiling on the `.md` read — accepted finding **[Should] #2** — that was never implemented when the base `.md`-viewer feature shipped 2026-07-15 outside the marathon process: *"The read is synchronous on `@MainActor` (`Focus5Model`), so cap it (e.g. read the first ~1 MB / N chars, append a '…truncated' note) to avoid freezing the UI on a huge file."*
  - `refreshTelemetry()`'s `.md` branch currently does an unbounded `String(contentsOf:)` read on the main actor — a large vault/telemetry `.md` file (misconfigured symlink, giant export, etc.) would freeze the panel with no bound.
  - Fix: cap the read at ~1 MB (read the file's data, truncate to the byte ceiling before UTF-8 decoding — do not decode-then-truncate, which can produce a broken multi-byte character at the cut point), and when truncated, append a visible `"…truncated (file exceeds 1 MB)"` note to `telemetryMarkdownContent` so the operator knows the view is partial, not corrupt.
- **Acceptance:** a `.md` file `>1MB` loads without freezing the panel and visibly shows the truncation note; a `.md` file `<1MB` is byte-identical to today's behavior (no regression on the common case); `swift test` green including a new size-ceiling test case; `swift build` (release) green; reinstalled via `make-app.sh` per standing guidance.
- **Out of scope:** no async/background-read rewrite (bigger change, not what the accepted finding asked for); no change to the JSON telemetry path; no new truncation UI beyond the one-line note.
