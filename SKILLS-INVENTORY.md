# Skills & Commands Inventory

Adopted from the GSD Core pattern review
([GH-103](https://github.com/Hypercart-Dev-Tools/rebalance-OS/issues/103) /
[GH-106](https://github.com/Hypercart-Dev-Tools/rebalance-OS/issues/106)): a lightweight,
generated-once index for discoverability and ownership visibility across the skill/command/hook
surfaces this repo actually uses. Deliberately **not** gsd-core's dynamic capability-overlay/trust
engine — this is a static reference doc, regenerated by hand when the inventory drifts, not a
runtime-loaded registry.

Scope: covers Rebalance-native skills/commands (this repo) plus the cross-repo surfaces this repo's
own docs (`PROJECT/PDDA.md`, this session's work) actually depend on. It does not attempt to catalog
the full global `~/.claude/skills/` catalog — that catalog is large, general-purpose, and owned
elsewhere; duplicating it here would drift immediately.

## Orchestrated flows (skill → command/tool → hook → owner)

Traced end-to-end, not just named — one real flow per row.

| Flow | Entry | Runtime surface | Hook | Owner |
|---|---|---|---|---|
| Onboarding | `/welcome` skill (`.claude/skills/welcome/SKILL.md`) | `mcp__rebalance__onboarding_status`, `mcp__rebalance__skip_onboarding_stage`, and related MCP tools drive each setup step | none wired | Rebalance |
| RAG query / refresh | `/ask_self`, `/reingest` commands (`.claude/commands/`) | shell out to the ask-self RAG tooling | none wired | Rebalance |
| Leaf-ingest bypass nudge | any `Bash` tool call | `PreToolUse` hook, `.claude/settings.json` | `utils/pdda/pdda-leaf-ingest-guard.py` (advisory only — see GH-106) | Rebalance |
| Automated cross-model review | `relay-xyz` skill (vendored, gitignored `.xyz/skills/relay-xyz/`) | `relay-automation/relay-drive.sh` + `codex-turn.sh`/`agy-turn.sh` shims | `relay-xyz-guard.sh` (path-allowlist + commit-bypass guard, blocking) | XYZ |
| One-shot cross-model consult | `consult` skill (canonical source: `xyz-3-agents-swarm/skills/consult/`) | `relay-automation/consult.sh` — throwaway git worktree isolation | none (isolation is the guard) | XYZ |

Note on the two XYZ rows: their exact file layout lives in the external `xyz-3-agents-swarm` harness
and a vendored, gitignored `.xyz/` copy in this repo — deliberately referenced by path/concept above,
not by line number, since that tree can change without notice from this repo's perspective (see
GH-106 discussion: another agent may be actively updating it).
