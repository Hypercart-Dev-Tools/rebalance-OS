## ⛔ Hard invariant — read this first

**Do NOT create a new time module, file, or utility class.** `src/rebalance/tz_utils.py`
already exists and is the single source of truth for time display. It landed 2026-07-16
via GH-130 ("centralize UTC→local time display"), went through a Codex relay review, and
ships with DST-boundary regression tests. It provides:

- `local_tz() -> ZoneInfo` — REBALANCE_TZ env > /etc/localtime > UTC
- `to_local(dt, tz=None)` — naive treated as UTC
- `parse_utc_iso(value) -> datetime | None` — handles trailing-Z and +HH:MM
- `format_local(value, fmt, *, tz=None) -> str` — parse-guard-convert-format core, `""` on failure
- `format_relative(value, *, now=None) -> str` — `just now` / `5m ago` / `3h ago` / `2d ago`

Your new helper **composes these**. Adding a parallel time helper re-opens exactly the
fragmentation GH-130 closed, and will be rejected at review.

```python
def format_timestamp(value, *, relative: bool = False, tz=None) -> str:
```

- Absolute form: `%Y-%m-%d %-I:%M %p` → `2026-07-17 8:02 PM`. Implement by delegating to
  the existing `format_local` — do not re-implement parsing or tz conversion.
- With `relative=True`, append ` · ` plus the existing `format_relative(value)` output:
  `2026-07-17 8:02 PM · 2h ago`.

  `""` — never emit a bare relative with no absolute anchor.
